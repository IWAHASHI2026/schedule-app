=============================================
  シフト自動生成ルール説明書
=============================================

このシステムでは、Google OR-Tools（CP-SAT ソルバー）を使って
最適なシフトを自動生成します。

ルールは 3 段階あります。

  絶対ルール       … 必ず守ります
  原則ルール       … 原則として守ります。どうしても守れない場合だけ破り、
                      「制約違反」として画面に表示します
  できるだけルール … 優先度の高いものから順に考慮する目標です


─────────────────────────────────────────────
■ 絶対ルール（必ず守られる制約）
─────────────────────────────────────────────

1. 希望休（終日）は必ず守る
   - 終日休（午前＋午後）→ その日は出勤しない

2. 1日1種類の仕事
   - 同じ日に複数の仕事種類を掛け持ちすることはない

3. 土日・祝日・会社の休業日は休み
   - 会社の休業日は「休日設定」で登録した日

4. 資格のある仕事のみ割り当て
   - スタッフ管理で設定された担当可能な仕事種類のみ割り当てる
   - 例：「職人」の資格がないスタッフに職人は割り当てない

5. 職人・サブ職人は1日に1名まで
   - 半日勤務のスタッフはこれらの役割には割り当てない

6. 必要人数を超えて配置しない
   - 必要人数設定の人数が、その日・その仕事の上限になる
   - lkデータ・uv/cpデータ・手紙が不足した場合は、不足した人数分だけ
     「その他」を増やせる
   - 例外：連休明け1日目は全員を出勤させるため、「その他」が
     必要人数を超えてもよい

7. 希望出勤日数「X日以内」を超えない
   - 半日勤務は0.5日としてカウント


─────────────────────────────────────────────
■ 原則ルール（守れない場合は「制約違反」として表示）
─────────────────────────────────────────────

1. 職人・サブ職人を毎営業日に1名ずつ配置する

2. 半日休（午前のみ or 午後のみ）の日は、残りの半日を出勤にする
   - 0.5人分として数える

3. 週間出勤上限を守る
   - 月曜〜日曜の1週間ごとに数える
   - 例：「週3日以内」→ 月〜金の営業日のうち最大3日まで出勤
   - 月をまたぐ週は、前月のシフトで出勤した日数も合わせて数える
     例：「週4日以内」で、前月のシフトで 9/28・29・30 に出勤
         → 同じ週の 10/1・2 は、どちらか1日まで出勤
   - 前月の出勤は、半日勤務も1日として数える
   - 前月のシフトは「公開中」のものを見る
     （公開中が無ければ、最後に作ったものを見る）
   - 前月のシフトがまだ無い場合は、その月の分だけを数える
   - 前月のシフトを後から直しても、作成済みのシフトは自動では変わらない
     （必要なときは再生成する）

4. 連休明け1日目は調整休を入れない
   - 通常の月曜、祝日や休業日の翌営業日が対象
   - 希望休・半日休のスタッフは対象外

5. 必要人数が設定されていない仕事には配置しない


─────────────────────────────────────────────
■ できるだけルール（優先度順に考慮される目標）
─────────────────────────────────────────────

以下のルールは「できるだけ」守りますが、上のルールや
他の条件との兼ね合いで完全には実現できない場合があります。
優先度の高い順に並んでいます。

1. 必要人数を満たす（優先度：最高）
   - 必要人数設定で入力した日別・職種別の人数をできるだけ確保する
   - 人手が足りない場合は、優先順位の低い仕事から人数を減らす
     職人 ＞ サブ職人 ＞ lkデータ ＞ uv/cpデータ ＞ 手紙 ＞ その他

2. 希望の出勤日数に近づける（優先度：高）
   - 希望日数の決まり方
       「なるべく多く」、未入力のフル勤務 … 出勤できる日すべて
       「X日以内」                       … その日数
       未入力の扶養内                    … 10日
   - 人が余る月は、誰かに調整休を入れる必要がある。
     調整休を入れる順番は次のとおり
       ① 扶養内のスタッフ
       ② フル勤務で「X日以内」のスタッフ
          扶養内のスタッフの調整休が1人あたり4日を超えるほど
          人が余る場合に限り、1日程度を入れる
       ③ フル勤務で「なるべく多く」のスタッフ
          原則として減らさない
   - 同じ順番の中では、希望日数から減らす日数が同じくらいになるように分ける
     （特定のスタッフに調整休が集中しないようにする）
   - 減らす日数をそろえるため、希望日数が少ないスタッフほど出勤日数も少なくなる
     例：3日ずつ減らす場合、「12日以内」の人は9日、「10日以内」の人は7日
   - 扶養内のスタッフの出勤日数に、下限の目安は設けていない
   - 条件が同じ場合は、フル勤務のスタッフを優先して配置する

3. 連休明け2日目はできるだけ出勤（優先度：高）
   - 2日以上の連休の翌々営業日が対象（通常の火曜など）
   - 必要人数の上限は超えない

4. 仕事種類のバランス（優先度：中）
   - 各スタッフの担当可能な仕事種類をまんべんなく割り当てる
   - 同じ仕事を担当できるスタッフの間で、日数の差を小さくする
   - サブ職人は特に均等にする
   - 担当可能な仕事が、月に1日も無い状態にならないようにする
   - 手紙は1人あたり週1日を基本とし、多くても週2日までにする

5. 連日同じ仕事を避ける（優先度：中）
   - 同じスタッフが連続する営業日に同じ仕事種類にならないよう配慮する
   - 担当可能な仕事が1種類しかないスタッフは対象外

6. 重要度の高い仕事を優先（優先度：低）
   - 職人 ＞ サブ職人 ＞ lkデータ ＞ uv/cpデータ ＞ 手紙 ＞ その他 の順で優先的に割り当てる


─────────────────────────────────────────────
■ 補足事項
─────────────────────────────────────────────

・生成にかかる時間は最大60秒です。
  60秒以内に最適解が見つからない場合は、その時点での最良の解を採用します。

・「制約違反」として表示される内容は、必要人数を満たせなかった日・職種と、
  守れなかった原則ルールの情報です。

・人が余る月に全員を希望どおり出勤させたい場合は、必要人数設定で
  「その他」の人数を増やしてください。必要人数が上限になっているため、
  増やした分だけ出勤できる人数が増えます。

・自然言語修正機能（Claude API）を使うと、生成後に
  「○○さんの職人を増やして」などの指示でシフトを調整できます。
